# Реконструкция MPI-изображений: сравнение классических и машинно-обучаемых методов

Дипломная работа (ВКР): исследование и разработка алгоритма машинного обучения
для задач реконструкции изображений магнитной частичной томографии (MPI).

> **Кому адресован этот документ.** Новому человеку (студенту-продолжателю,
> рецензенту, комиссии) с базовым знанием машинного обучения и Python.
> Здесь объясняется: что делает проект, как он устроен, где какой код,
> как всё запустить и воспроизвести.

---

## 1. Что это за проект

MPI (Magnetic Particle Imaging) — метод медицинской визуализации, который
определяет распределение магнитных наночастиц внутри объекта по измеренному
сканером сигналу. Задача реконструкции — восстановить карту концентрации
частиц `c` из измеренного сигнала `u`:

    u = A · c + noise

где `A` — так называемая **системная матрица** (как делает сканер: отклик
на единичную концентрацию в каждой точке пространства). Обратная задача
некорректна — малые помехи в измерении сильно искажают ответ.

Проект сравнивает **два семейства подходов** к реконструкции:

- **Классические (без машинного обучения):** Тихонов, Качмарж (Kaczmarz/ART),
  LSQR. Работают через прямое решение обратной задачи.
- **Нейросетевые:**
  - *обучаемые на размеченных парах* (`supervised`): CNN (U-Net), MoDL,
    Chae 2017, DDPM-диффузия;
  - *без обучающей выборки* (`data-free`, подстраиваются под каждое
    измерение отдельно): DIP (2020), PMCNet (2026) и его варианты;
  - *комбинированные*: Mixture of Experts (объединение нескольких методов).

Качество оценивается метриками **SSIM** (структурное сходство), **PSNR**
(отношение сигнал/шум), **FWHM** (разрешение) и временем реконструкции.

## 3. Как устроен основной пайплайн (карта `pipeline.py`)

`ML/src/pipeline.py` — сердце проекта (~1400 строк). Всё начинается из
`ML/run.py`, который вызывает единственную функцию `run_pipeline()`.
Шесть крупных шагов:

```
1. Генерация синтетических данных
   └─ два независимых пути, чтобы проверить обобщаемость:
        • SM-путь  — изображение → сигнал через ИЗМЕРЕННУЮ системную матрицу;
        • physical — изображение → сигнал через АНАЛИТИЧЕСКУЮ физику
                     (формулы MPI, без матрицы).
2. Обучение всех моделей (или загрузка готовых весов)
   └─ классические (Тихонов, Качмарж) — не обучаются;
   └─ обучаемые сети (CNN, MoDL, Chae, Diffusion) — веса в DATA/models/;
   └─ data-free методы (DIP, PMCNet) — обучаются под каждое измерение.
3. Сборка тестовой батареи фантомов (6 типов: капли, крест, кольцо, ...)
4. Запуск сравнительной таблицы: каждый метод × каждый фантом × 2 пути
   └─ метрики SSIM/PSNR/FWHM/время → единая таблица + картинки.
5. (опционально) MoE — комбинирование нескольких методов.
6. (опционально) Валидация на реальных данных OpenMPI.
```

**Как читать код по шагам (рекомендуемый порядок):**
1. `ML/run.py` — параметры запуска (что можно менять).
2. `ML/src/pipeline.py` — docstring в начале модуля + шапка `run_pipeline`
   (там честно описан весь поток).
3. `ML/src/data/` — как создаются/загружаются данные.
4. `ML/src/models/` — сами модели (по файлам, см. таблицу моделей ниже).
5. `ML/src/comparator.py` + `metrics.py` — как считается качество.

Основные «переключатели» в `run.py`:

| Параметр                | Назначение                                             | По умолчанию |
|-------------------------|--------------------------------------------------------|--------------|
| `NUM_SAMPLES`           | размер обучающего синтетического датасета              | `5000`       |
| `TRAIN_MODELS`          | `True` — обучать сети; `False` — загрузить готовые веса| `True`       |
| `PMCNET_ITER`           | число итераций для data-free методов (DIP, PMCNet)     | `5000`       |
| `FORCE_REGENERATE_DATASET` | `True` — пересоздать датасет с нуля                 | `False`      |
| `VALIDATE_OPENMPI`      | `True` — добавить проверку на реальных данных OpenMPI  | `False`      |

## 4. Чужой и свой код

В корне репозитория лежит код, который **не написан автором работы** —
это референсная реализация от автора китайского датасета (Chae et al., 2017):

- `main.py`, `ReconstructionMethod.py`, `Nargout.py`, `readme.txt`.

Их можно открывать как пример работы с H5-данными сканера, но именно авторский результат — весь основной вклад — находится в каталоге **`ML/`**.

> `Nargout.py` эмулирует поведение MATLAB-функции `nargout`; `main.py` —
> демонстрационный скрипт реконструкции методом Тихонова.

PDF-файлы — научные статьи и пособия, по которым делалась работа; они не код
и вынесены в отдельную папку **`Литература/`**. Краткие аннотации по каждой
статье — в `Литература/Аннотации литературы.md`.

## 5. Установка и запуск

### Установка окружения

Работали на **Python 3.11 / 3.12**. Рекомендуется отдельное виртуальное
окружение:

```bash
python -m venv .venv
# Windows:  .venv\Scripts\activate    Linux/macOS: source .venv/bin/activate
pip install -r requirements.txt
```

> Для ускорения на видеокарте (CUDA) поставьте `torch` с поддержкой CUDA
> отдельно по инструкции с сайта PyTorch, а затем остальные пакеты.

### Запуск эксперимента

```bash
cd ML
python run.py
```

Что произойдёт: при первом запуске сгенерируются синтетические данные
(несколько минут), обучатся все сети, и в конце напечатается итоговая
таблица сравнения методов. Результаты и картинки появятся в `ML/DATA/results/`.

## 6. Как воспроизвести эксперимент (готовые рецепты)

### Быстро посмотреть результаты БЕЗ обучения

Уже сохранённые веса лежат в `ML/DATA/models/`. Чтобы прогнать сравнение
на имеющихся моделях, не тратя часы на обучение:

```python
# в ML/run.py:
TRAIN_MODELS = False     # загрузить готовые веса вместо обучения
# также можно уменьшить PMCNET_ITER до 500–1000 для быстрой проверки
```

### Полный повторный прогон «с нуля»

```python
# в ML/run.py:
TRAIN_MODELS = True
FORCE_REGENERATE_DATASET = True   # пересоздать данные и поднять объём
NUM_SAMPLES = 5000
```

⚠️ **Внимание:** полный прогон, особенно data-free методы (PMCNet,
`PMCNET_ITER=5000`), занимает **значительно время*. При тестировании снижайте `PMCNET_ITER`.

### Проверка на реальных данных OpenMPI

1. Положите данные в `mpi/ChineseData/OpenMPIData/` со структурой:
   ```
   calibrations/    ← *.mdf (системные функции)
   measurements/    ← подпапки backgroundDrift/, concentrationPhantom/,
                      resolutionPhantom/, rotationPhantom/, shapePhantom/
                      с *.mdf внутри
   ```
2. В `run.py` поставьте `VALIDATE_OPENMPI = True`.

Если папки с данными нет — валидация просто пропускается, без ошибки.

### Как сгенерировать отдельные классические методы

Классические методы (Тихонов, Качмарж, LSQR) и их результаты —
в `ClassicAlgorithms/` (CSV-отчёт и картинки). Они вызываются и внутри
`ML/`, так что отдельно запускать их не обязательно.

## 9. Ключевые термины (мини-глоссарий)

- **Системная матрица (SM)** — как сканер преобразует концентрацию частиц
  в сигнал; `u = S·c`.
- **Фантом** — искусственное изображение-эталон с известным правильным
  ответом, на котором оценивают методы.
- **`supervised`** — обучение на размеченных парах «измерение → изображение».
- **`data-free`** — метод не требует обучающей выборки, подстраивается
  под каждое измерение отдельно (DIP, PMCNet).
- **Глоссарий по физике (Ланжевен, FFP-траектория, драйв-поле и т.д.)** —
  см. `theory mpi.md`.
